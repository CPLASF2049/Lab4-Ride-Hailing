## 一、服务注册与发现

- 为业务服务配置注册与发现，使 API 网关及服务调用方能够通过服务名称定位目标服务实例。

- 可以使用应用层注册中心，也可以使用部署平台提供的服务发现机制。

- 服务实例启动、退出或数量变化后，服务发现结果能够相应更新。

报告内容：说明所选方案、各服务实例如何注册或被发现，以及网关和服务调用方如何获取并使用实例信息。

## 四、服务容错

选择一个 `order-query` API，建议使用 Lab3 中的组合查询接口，在该接口及其依赖调用上实现以下策略。可通过框架配置或代码实现，具体组件与实现位置由小组选择。

- 超时：设置请求或依赖调用的超时时间，明确超时后的处理方式。可由 HTTP/RPC 客户端或网关控制，例如 Gateway 超时配置。

- 重试：实现重试机制，明确适用的失败条件、最大重试次数及重试间隔。可通过代码、客户端重试机制或网关实现，例如 Gateway Retry。

- 限流：在网关或服务中实现请求频率或并发量限制，明确限制的作用范围和被限流后的响应。也可使用 Sentinel，它支持服务内限流，也支持集成网关限流。

- 熔断：设置熔断触发条件、等待时间及恢复探测策略。可使用 Sentinel 熔断，根据慢调用比例、异常比例或异常数量触发。

- 降级：结合查询场景，返回可用的部分数据或明确的暂不可用信息。可使用 Sentinel 提供的 `blockHandler`、`fallback` 等处理入口，并通过业务代码实现具体的降级逻辑，参考 Sentinel 注解说明。

例如，查询订单详情时，订单读模型正常，但获取司机补充资料的接口响应缓慢或调用失败，可以围绕这条调用链配置上述策略。

通过模拟依赖延迟、短暂失败、持续失败和请求量增加，验证相应策略的触发效果及依赖恢复后的表现。

报告内容：说明所选 API、相关调用链、五项策略的实现位置、关键参数及选择理由，并记录验证方法、实际响应和必要日志。

## 五、服务水平扩缩容

为 `order-query` 实现水平扩缩容，演示从 1 个实例扩容至至少 2 个实例，再缩容回 1 个实例。

根据所选部署平台完成以下要求：

- Docker Compose：使用 Compose 扩缩容命令 调整实例数量，完成扩容与缩容。

- Kubernetes：配置 HPA 实现自动扩缩容，接入相应的指标来源，根据负载自动调整 Deployment 副本数。演示负载增加时自动扩容、负载回落后自动缩容；使用 CPU 或内存指标时，可通过 Metrics Server 提供指标。

报告内容：说明扩缩容配置与操作方式，记录扩缩容前后的实例数量。使用 Kubernetes 时，补充 HPA 的触发指标、目标值或阈值、实例数量上下限，以及自动扩缩容过程中的指标变化。

## 六、契约测试

保留 Lab3 已有的测试，选择一个实际使用的服务接口完成契约测试。例如，选择 `order-query` 获取司机资料时调用的接口。

- 在提供者侧验证实际接口符合契约，在消费者侧验证调用和响应处理符合相同契约。

可参考课件使用 Spring Cloud Contract，也可选择 Pact 等适合本组技术栈的工具。

报告内容：说明所选接口、提供者与消费者、契约内容、双方的测试方式及执行结果。
